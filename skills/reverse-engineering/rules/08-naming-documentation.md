# Rule 8: Naming & Semantic Documentation

## Mandate
Immediately upon identifying or confirming the functional role of a subroutine, local variable, global buffer, or struct field, rename the identifier in the target database and record it in `re_state.json`:

| Tool | Function or global | Local variable |
|---|---|---|
| IDA 9.x via ida-mcp `execute_python` | `ida_name.set_name(ea, "decrypt_config", ida_name.SN_NOWARN \| ida_name.SN_NOCHECK)` (returns `False` on a bad or duplicate name) | `ida_hexrays.rename_lvar(func_ea, "a1", "p_cipher_buf")` |
| Ghidra (PyGhidra / script) | `func.setName("decrypt_config", SourceType.USER_DEFINED)` | `HighFunctionDBUtil.updateDBVariable(sym, "p_cipher_buf", None, SourceType.USER_DEFINED)` |
| radare2 | `afn decrypt_config @ 0x401120` | `afvn p_cipher_buf arg1` |

Save the database after a batch of renames (`save_database` in ida-mcp; Ghidra saves on `program_context` exit). A rename that is not saved is lost when the worker closes. Scale renames from a mapping file as shown in [ida-pro.md](../references/04-tool-usage/ida-pro.md).

## Semantic Naming Over Generic Defaults
Never leave generic or autogenerated disassembler names in place once their purpose has been determined.
- **Functions**: Replace generic prefixes (`sub_140001020`, `FUN_00401050`) with clear action-oriented semantic names:
  - `decrypt_config`
  - `verify_license_key`
  - `parse_tlv_packet`
  - `resolve_api_hashes`
- **Variables & Arguments**: Replace default labels (`a1`, `v4`, `pvVar2`) with domain-accurate representations:
  - `p_cipher_buf`
  - `key_len`
  - `sockfd`
  - `status_code`
- **Structs**: Declare structured data types rather than indexing raw byte offsets (`*(DWORD *)(ctx + 16)` becomes `ctx->timeout_ms`).

## Semantic Annotation Standards
Add concise inline comments explaining non-obvious logic:
1. **Magic Constants**: Document algorithmic constants (e.g. `0xEDB88320` -> CRC32 polynomial; `0x67452301` -> MD5/SHA1 initial vector).
2. **Bitwise Arithmetic**: Clarify packing or unpacking masks (e.g. bit extraction of flags or packed protocol headers).
3. **Implicit Side Effects**: Document modifications to global state, thread-local storage, or hardware registers.

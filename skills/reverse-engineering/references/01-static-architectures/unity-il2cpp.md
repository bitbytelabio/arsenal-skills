# Unity IL2CPP Reverse Engineering

## 1. Title & Overview
- **Domain**: Unity games and cross-platform applications compiled with the Intermediate Language to C++ (IL2CPP) backend.
- **Scope**: Parsing `global-metadata.dat` structures and version headers, mapping method function pointers against native binaries (`libil2cpp.so`, `GameAssembly.dll`, or Mach-O executable), inspecting `Il2CppClass` and `Il2CppObject` runtime memory layouts, generating dummy .NET assemblies (`DummyDll`), importing symbol scripts into IDA Pro and Ghidra, and overcoming metadata encryption and obfuscation.

---

## 2. Trigger Conditions & Detection Indicators
Engage this reference when analyzing applications compiled with Unity's IL2CPP toolchain:

### Binary Signatures & Artifact Detection
- **Metadata File Presence**:
  - Android APK: `assets/bin/Data/Managed/Metadata/global-metadata.dat`
  - Windows: `<GameName>_Data/il2cpp_data/Metadata/global-metadata.dat`
  - iOS IPA: `Payload/<AppName>.app/Data/Managed/Metadata/global-metadata.dat`
- **Native Binary Companion**:
  - Android: `lib/<abi>/libil2cpp.so`
  - Windows: `GameAssembly.dll`
  - iOS: Main Mach-O binary or `Frameworks/UnityFramework.framework/UnityFramework`
- **Magic Bytes & Header Signatures**:
  - `global-metadata.dat` header magic (4 bytes):
    - Little-endian: `0xFAB11BAF` (`\xAF\x1B\xB1\xFA`)
    - Big-endian: `0xAF1BB1FA`
  - Native binary exports:
    - `il2cpp_init`, `il2cpp_class_get_methods`, `il2cpp_domain_get`, `il2cpp_runtime_invoke`
  - String literals inside native binary:
    - `il2cpp::vm::MetadataCache`, `il2cpp_codegen_initialize_method`

## 3. Tooling & CLI/MCP Actions
- **Primary IL2CPP Dumper Utilities**:
  - `Il2CppDumper`: Extracts types, methods, fields, and string literals, generating stub DLLs and symbol scripts.
    ```bash
    # Standard syntax: Il2CppDumper <executable> <global-metadata.dat> <output_dir>
    Il2CppDumper libil2cpp.so global-metadata.dat ./il2cpp_out
    ```
  - `Il2CppInspector`: Advanced CLI generating high-level C++ scaffolding and Ghidra/IDA Python plugins.
    ```bash
    Il2CppInspector -b libil2cpp.so -m global-metadata.dat --dump-all
    ```
  - `Cpp2IL`: Restores IL instructions and decompiles to readable high-level C# pseudocode.
    ```bash
    Cpp2IL --game-path /path/to/game --exe GameAssembly.dll
    ```
- **Disassembler / Decompiler Integration**:
  - IDA Pro: Run `ida_with_struct_py3.py` (generated by Il2CppDumper) to rename functions, apply struct types, and tag string literals.
  - dnSpyEx / ILSpy: Open stub assemblies in the generated `DummyDll/` folder (specifically `Assembly-CSharp.dll`) to browse the recovered C# type system.

## 4. Core Methodologies & Step-by-Step Technical Workflow

### 4.1 Metadata Header Parsing & Version Matching
The `global-metadata.dat` file contains all class definitions, method names, field names, and type definitions referenced by the compiled native binary.

#### Metadata Header Structure:
```c
struct Il2CppGlobalMetadataHeader {
    uint32_t magic;                    // 0xFAB11BAF
    int32_t  version;                  // IL2CPP metadata version (e.g., 24, 27, 29, 31)
    int32_t  stringLiteralOffset;      // Array of Il2CppStringLiteral
    int32_t  stringLiteralSize;
    int32_t  stringLiteralDataOffset;  // UTF-8 string literal data blob
    int32_t  stringLiteralDataSize;
    int32_t  stringOffset;             // Identifier strings (#Strings equivalent)
    int32_t  stringSize;
    int32_t  eventsOffset;             // Event definitions
    int32_t  eventsSize;
    int32_t  propertiesOffset;         // Property definitions
    int32_t  propertiesSize;
    int32_t  methodsOffset;            // Method definitions (Il2CppMethodDefinition)
    int32_t  methodsSize;
    int32_t  typeDefinitionsOffset;    // Type definitions (Il2CppTypeDefinition)
    int32_t  typeDefinitionsSize;
    int32_t  imagesOffset;             // Assembly definitions (Assembly-CSharp, etc.)
    int32_t  imagesSize;
    // ... Additional offsets for fields, parameters, generic containers
};
```

#### Metadata Versions across Unity Releases:
- Unity 2018.3 – 2019.2: Metadata version `24`
- Unity 2019.3 – 2020.1: Metadata version `24.2` / `27`
- Unity 2020.2 – 2021.2: Metadata version `27.1` / `27.2`
- Unity 2021.3 – 2022.1: Metadata version `29`
- Unity 2022.2 – 2023.2+: Metadata version `31`

---

### 4.2 Mapping Method Pointers Against Native Code
Because C++ lacks managed reflection, IL2CPP compiles every C# method into a standalone C++ function and stores function pointers in a registration table (`Il2CppCodeRegistration`).

#### The Matching Mechanism:
1. `global-metadata.dat` assigns an incremental `MethodIndex` to each method definition.
2. The native binary (`libil2cpp.so` or `GameAssembly.dll`) contains a static array of function pointers (`methodPointers`):
   ```c
   void* methodPointers[] = {
       &AssemblyCSharp_PlayerController_Update,  // Index 0
       &AssemblyCSharp_PlayerController_Jump,    // Index 1
       &AssemblyCSharp_NetworkManager_Connect,   // Index 2
   };
   ```
3. `Il2CppDumper` locates `methodPointers` in the native binary by scanning for the initialization sequence inside `il2cpp::vm::MetadataCache::RegisterCodeRegistration` or by cross-referencing known pointer tables.
4. By correlating `methodsOffset[MethodIndex]` in `global-metadata.dat` with `methodPointers[MethodIndex]` in the binary, every native function is resolved to its original C# namespace, class name, method name, and signature.

### 4.3 Runtime Layout: `Il2CppObject` and `Il2CppClass`

#### Object Instance Layout (`Il2CppObject`):
Every managed C# heap object instance instantiated in IL2CPP begins with an 8-byte pointer to its `Il2CppClass` definition, followed by monitor/lock synchronization data:
```c
struct Il2CppObject {
    Il2CppClass* klass;     // [+0x00]: Pointer to class descriptor (vtable, methods, fields)
    void*        monitor;   // [+0x08]: Thread synchronization lock / monitor
    // [+0x10]: Instance fields defined by the C# class begin here
};
```

#### Class Descriptor Layout (`Il2CppClass`):
The class descriptor contains static fields, the virtual method dispatch table, and runtime type information:
```c
struct Il2CppClass {
    void*               image;               // Pointer to Il2CppImage (e.g., Assembly-CSharp)
    void*               gc_desc;             // GC allocation descriptor
    const char*         name;                // Class name ("PlayerController")
    const char*         namespaze;           // Namespace ("Game.Controllers")
    Il2CppType          byval_arg;
    Il2CppType          this_arg;
    Il2CppClass*        element_class;
    Il2CppClass*        castClass;
    Il2CppClass*        declaringType;
    Il2CppClass*        parent;              // Superclass descriptor
    void*               generic_class;
    Il2CppTypeDefinition* typeDefinition;    // Direct link back to global-metadata.dat
    void*               interopData;
    Il2CppClass*        klass;
    FieldInfo*          fields;              // Field descriptor array
    EventInfo*          events;              // Event descriptor array
    PropertyInfo*       properties;          // Property descriptor array
    MethodInfo**        methods;             // Method descriptor array
    Il2CppClass**       nestedTypes;
    Il2CppClass**       interfaces;
    void*               interfaceOffsets;
    void*               static_fields;       // Pointer to heap block storing static variables
    void*               rgctx_data;
    // ... VTable array begins here
    VirtualInvokeData   vtable[32];          // Array of virtual method function pointers
};
```

#### IL2CPP Method Calling Convention:
Every IL2CPP compiled method expects a hidden pointer to the method's own metadata descriptor (`MethodInfo*`) passed as the **last parameter**:
```c
// C# signature: public void TakeDamage(int damage)
// Native compiled IL2CPP signature:
void PlayerController_TakeDamage(PlayerController* this, int32_t damage, const MethodInfo* method);
```
- In x86-64 System V: `RDI` = `this`, `ESI` = `damage`, `RDX` = `method`
- In ARM64: `X0` = `this`, `W1` = `damage`, `X2` = `method`

### 4.4 Recovering Types via Dummy DLLs
`Il2CppDumper` generates a set of mock .NET assemblies in the `DummyDll/` folder:
- These assemblies contain complete class definitions, method declarations, attributes, and field offsets, with empty method bodies containing single `throw null;` stubs.
- **Workflow**:
  1. Open `DummyDll/Assembly-CSharp.dll` in dnSpyEx or ILSpy.
  2. Search for high-value game logic: e.g., `GameManager`, `EncryptionKey`, `PurchaseValidator`, `AntiCheat`.
  3. Inspect method declarations to find the virtual memory address annotation:
     ```csharp
     // RVA: 0x00A4BC20 Offset: 0x00A4BC20 VA: 0x00A4BC20
     public bool ValidateLicense(string token) { }
     ```
  4. Jump directly to address `0x00A4BC20` in your native disassembler (IDA Pro / Ghidra) to view the actual C++ assembly and pseudocode.

---

### 4.5 Handling Obfuscated and Encrypted Metadata
Commercial mobile games often encrypt `global-metadata.dat` or erase the `0xFAB11BAF` magic bytes:

1. **Magic Header Zeroing**:
   - Protectors overwrite the first 4 bytes with zeroes or random noise.
   - Fix: Hex-edit the first 4 bytes back to `AF 1B B1 FA` and check if version follows at offset `0x04`.
2. **Encrypted Metadata**:
   - If entropy is close to 1.0 or strings are unreadable, the game decrypts metadata in memory at startup before calling `il2cpp_init`.
   - **Resolution via Memory Dump**:
     - Run the application on a rooted Android device or emulator.
     - Attach Frida or use a memory dumper script to intercept `il2cpp_init`.
     - Dump the decrypted metadata buffer directly from the first argument passed to `il2cpp::vm::MetadataCache::Initialize()`.

## 5. Concrete Code & Script Examples

### Frida Script to Dump Decrypted `global-metadata.dat` from Memory
```javascript
// Frida script to dump decrypted global-metadata.dat at runtime
function dumpMetadata() {
    var il2cpp = Process.findModuleByName("libil2cpp.so");
    if (!il2cpp) {
        console.log("[-] libil2cpp.so not loaded yet, retry shortly.");
        return;
    }
    console.log("[+] Found libil2cpp.so base: " + il2cpp.base);

    // Search for il2cpp_init export
    var il2cpp_init = il2cpp.findExportByName("il2cpp_init");
    if (il2cpp_init) {
        Interceptor.attach(il2cpp_init, {
            onEnter: function (args) {
                console.log("[+] il2cpp_init called! Searching for decrypted metadata in memory...");
            },
            onLeave: function (retval) {
                // Scan memory ranges of the process for global-metadata magic: 0xFAB11BAF
                var ranges = Process.enumerateRanges('r--');
                for (var i = 0; i < ranges.length; i++) {
                    var range = ranges[i];
                    try {
                        var match = Memory.scanSync(range.base, range.size, "af 1b b1 fa");
                        if (match.length > 0) {
                            var metaAddr = match[0].address;
                            var version = metaAddr.add(4).readU32();
                            console.log("[*] Found metadata header at: " + metaAddr + " | Version: " + version);
                            
                            // Dump first 1MB or full size to file
                            var dumpSize = 10 * 1024 * 1024; // 10MB conservative buffer
                            var buf = metaAddr.readByteArray(dumpSize);
                            var file = new File("/data/data/" + Process.getCurrentProcess().name + "/dumped_metadata.dat", "wb");
                            file.write(buf);
                            file.close();
                            console.log("[+] Dumped decrypted metadata to app internal directory!");
                            break;
                        }
                    } catch (e) {}
                }
            }
        });
    }
}

setImmediate(dumpMetadata);
```

## 6. Boundaries & Anti-Patterns
- **Do not reverse `libil2cpp.so` without metadata**: Attempting to decompile `libil2cpp.so` without first running Il2CppDumper or restoring symbols is counter-productive. All user classes, methods, and variables will be anonymous stripped addresses.
- **Do not decompile boilerplate Unity engine code**: Focus strictly on `Assembly-CSharp.dll` and developer-specific assemblies. Do not spend time analyzing `UnityEngine.CoreModule.dll`, `mscorlib.dll`, or `System.dll`.
- **Do not ignore the trailing `MethodInfo*` argument**: When writing Frida hooks or patching IL2CPP methods, remember that native signatures contain the hidden `MethodInfo*` parameter. Omitting it from calling conventions will corrupt stack frames on 32-bit architectures or clobber registers.
- **Do not assume `dump.cs` contains method code**: `dump.cs` contains only type definitions and function declarations annotated with virtual addresses. The executable code lives exclusively inside `libil2cpp.so` / `GameAssembly.dll`.
